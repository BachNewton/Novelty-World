# Åland Drive: tools and labs

The headless tools that measure and check the game, and the dev pages built on the real game. Paths are relative to the project's folder, `src/projects/aland-drive/`; the project's own `CLAUDE.md` there is the overview and says where everything else is written down.

## Tools

The tools run against local tiles, never the real host: `tools/serve-tiles.mjs` serves a folder of them and counts the bytes it sent, and a page takes it with `?tiles=local:<port>`. `tools/look.mjs` takes a screenshot from any place on the map, on the integrated Radeon unless `--egpu` puts it on the eGPU, for what shows on Nvidia alone. `tools/shader-count.mjs` counts what a cold page compiles, every WebGPU shader module and pipeline from the device's own calls, grouped by what each pipeline's vertex shader reads: the same on every run, so a change to the start-up compile is judged by it. A `select` in a shader that chooses between anything but plain values is written by three as two branches, so a blend by a 0-or-1 weight is used instead where both sides are worked out anyway. **A node two branches share is nothing in the second**: three declares every node's variable at the top of the function and assigns it where the node is first built, so a node first read inside one branch of a `select` or an `If`, and read again in the other branch or after them, compiles and is zero there. `tools/unset-reads.mjs` finds every such read in a dump of the modules, and `shader-count.mjs` prints them with the pipelines they belong to, so a change to a shader's branches is checked by it. What branches share is given to the stack before them (`toVar()` as a statement of the `Fn`, read later, since a var nothing reads is dropped), or takes a node of its own in each branch, or the branch is made a blend. Three more ways a shader is compiled more than it needs: TSL writes a function's whole body at each place its result is read, so a function whose struct is read field by field is read once, into what uses all of it (the wall's colour and glow were its biggest shader twice over); a node made inside a function's body is a new one each time three builds the material, so an array a material reads is made outside it; and a uniform array is named in the shader by the node it is, so materials alike but for their own copy of a kit's palette are each a pipeline, and a kit's palette is made once (`art/palette.ts`). A planting's lattices are culled by one kernel unless its rule differs by lattice (`byLattice`). `tools/drive.mjs` drives a route the game's own GPS sets (`--gps=<x,z;x,z;...>`) and prints what it did, cost, held and downloaded, held and stepped by hand, or with `--clock` at real speed, which is the one that says whether anything stalled. The LOD check, `art/lod-check/check.mjs`, measures where every model swaps to its far version and holds `swaps.json` to the art; it is run by hand when art changes (`art/CLAUDE.md`). `tools/landings.mjs` walks the load focus round the world so tiles land over and over, and prints what each cost. `tools/film.mjs` makes a video from one, for judging what moves: it takes over the page's clock and renders each frame a frame's time after the last, so the video plays at real speed however slowly the machine renders, with the boats' clock set where the video starts and, for a ship's slow manoeuvre, sped up on its own (`--speed`); ffmpeg encodes it. `tools/road-check.ts` drives every motor road in the simulation alone, `tools/car-limits.ts` measures every car's grip, braking and pull on a flat test pad (`sim/test-pad.ts`) of each surface in each condition into the table the racers will read (`sim/car-limits.json`), `tools/bridge-check.ts` every span, both ways, and `tools/junction-check.ts` every way through every junction of a tile (see "How rough the roads are" in `pipeline/CLAUDE.md`). The browser tools use headless Playwright with `channel: "chromium"`, because the default headless shell falls back to WebGL2 here.

## Measuring what a frame costs

Speed here is counted, never timed (the repo's speed rule, and "Measure by counts" in the project's `CLAUDE.md`): the counts below are the same on every run whatever the machine is doing, so a change is judged by the difference, exact.

`tools/frame-cost.mjs` counts what a frame costs at the showcase views, or at looks of one's own, with `tools/gpu-meter.mjs`: a script that runs in the page before the game and wraps the WebGPU API the game is given, so every draw, dispatch, upload and pipeline is written down as it's encoded, and nothing in the game changes for it. Every depth buffer becomes a depth-stencil one whose stencil counts the fragments written at each pixel, summed by a compute pass of the meter's own. For one frame, held still, it prints each pass's draw calls, triangles and vertex shader invocations (an indirect draw's arguments read back from the GPU, so the forest and the plantings count), the fragments shaded and the overdraw they make, the bytes each pass's attachments load, store and resolve (the frame-buffer traffic a bandwidth-bound GPU pays), the compute invocations, the bytes uploaded, and GPU time as context only. The scene pass is the pass with the most draws: three draws the scene into an offscreen target and blits it to the canvas through its output colour transform, which the tool shows as a second pass. `--draws` attributes the fragments to each draw and so to each pipeline, redrawing the held frame once per draw with the draws after it skipped; a list a compute pass fills comes out in an order that changes by the frame and what it writes changes with it, so under the default count of what's written those lists are told as one group, and `--fragments=rasterized`, which counts every fragment that reached the depth test, is exact for every draw. `--image` saves an overdraw picture beside a screenshot of each view, `--save` keeps a run as JSON and `--against` prints each view's change from a saved one. Each planting's lists are printed against their room, since a full list drew its first plants and dropped the rest. A fragment the shader discards never reaches the stencil, so a screen-door dissolve is shaded twice and counted as neither.

`tools/frame-diff.mjs` is the proof a change is pixel-identical, or the measure of how far it isn't: two builds' pages, one on each build's server (a dev server in each worktree), on a clock of the tool's own that moves only by whole frames (`game-page.mjs`, `clock`), so every clock the game keeps is at the same place in both once both have drawn the same number of frames; at each view both are jumped, settled, drawn level and shot, with the HUD hidden, and compared pixel by pixel, with a picture of what differs. For that to hold, nothing drawn may run on the renderer's own clock, which counts from before the game loads: the water's ripples and the traffic lights run on the game's world clock. Two coplanar faces at exactly one depth swap winner with the draw order, so a change to the order alone shows a handful of pixels a view, by a few levels. A branch that replaces a blend by exactly 0 or 1 isn't pixel-identical either: the blend still rounded through the side it dropped, and the dither turns that last bit into a level at scattered pixels, water's glints far off into more; a real change shows as a region, or as levels no dither makes.

`tools/frame-cpu.mjs` counts the main thread's side of the same held frame: every function the frame calls and how many times, from V8's own invocation counts (its precise coverage), grouped by module and by the work that matters on its own (the objects three visits, the render objects it prepares and the draws it issues, the matrices composed, the uniforms compared, the bind groups and buffers written), and the bytes the frame allocates, as the heap's growth over one frame after a full collection, with the sites that allocate sampled. V8 counts calls only in code its optimising tiers haven't compiled, so the calls are counted in a browser with the tiers off, and the bytes in one with them on, since the interpreter boxes every number and would allocate what the game never does; the dev bundle reads every imported binding through a getter of its own, which the tool counts apart. `--free` measures each view again with the simulation running, where the steps and the traffic count too. A function called for every object every frame, or a check re-done each frame for something that changes only when a tile lands, shows here and nowhere else.

`tools/load-count.mjs` counts what starting the game costs, on a cold page on the tool's clock: every request as served (by what the file is: the page's scripts, each kind of tile file), the shader modules and pipelines compiled (`tools/device-watch.mjs`, the watcher `shader-count` uses too), and the frames drawn, read at every step of the start: the page's load event, the game's script running, each count the start bar shows, the bar going, the map ready. Requests, bytes, modules and pipelines are the same on every run; the tick each step came at is this machine's, printed as context. A dev server serves the page's scripts unminified, so their bytes are the dev build's; the tiles' bytes are a player's.

The GPU's time printed beside the counts is the frame's, on this machine, under whatever else it was doing: it says whether the counts were worth having, never which change to keep.

## Labs

`?junction-lab` is the real game with the hardest junctions of each kind a click away (`render/junction-spots.ts`, `components/junction-lab.tsx`), from above, at a driver's eye or at the wheel, with the car on the approach, to judge a change to the road surface. `?forest-lab` is the forest on its own (`render/forest-lab.ts`, `components/forest-lab.tsx`), on the game's own forest and terrain code and real tiles, to see how its detail works and to judge a change to it. What detail is measured from can be pinned away from the camera, so a tree goes through everything a drive does to it with the view held still. It colours trees by model, by whether they're mid-change and by how far their base slides, finds the worst trees nearby, changes the forest's settings live, and shows how many trees each list drew; `?date=` shows it in that date's season. `render/tile-reads.ts` is what the game and the lab share, so the lab's trees are the game's. `?deer-lab` is `art/deer`'s gallery running live (`art/deer/stage.ts`, `components/deer-lab.tsx`): every kind in every gait, each gait held through its cycle, a doe and her kids crossing a road, the seasons and the speed to judge the gaits by, flown with the free camera.
