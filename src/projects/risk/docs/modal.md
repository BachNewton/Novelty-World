# Training on Modal's GPUs

The GPU trainers (`gpu/riskgpu/selfplay/ppo.py`, and `imitate.py`'s imitation), and one-off readings of checkpoints by the diagnostic tools, can run on Modal (modal.com) as well as on the laptop's eGPU and Kaggle (`kaggle.md`). Modal bills by the second for the GPU, the cores and the memory a container holds; the free plan gives $30 of credit a month, and the owner's workspace caps its usage at $30, so a month's credit is the budget. On the Risk trainer an A10 gives the most training per dollar (the machine-learning skill's `references/budget.md`, from `gpu/riskgpu/modalgpu/bench.py`), at about the eGPU's speed; an H100 the most per hour. `gpu/riskgpu/modalgpu/launch.py` drives it from here, run from `src/projects/risk/gpu/`, with the Kaggle launcher's jobs in the Kaggle launcher's terms, so a session can use either.

## The one-time setup (the owner's)

A Modal account with a card on file (no GPU runs without one), and the client installed and signed in on this machine: `pip install modal`, then `modal setup`. `modal billing summary` shows the month's spend.

## A run

```bash
python -m riskgpu.modalgpu.launch push <name> [<name>] [--imitate] [--gpu A10] [--hours 8] [--read-hours 2] [--dry-run] -- <trainer arguments>
python -m riskgpu.modalgpu.launch status <name> [<name>]
python -m riskgpu.modalgpu.launch stop <name> [<name>]
python -m riskgpu.modalgpu.launch fetch <name> [<name>]
python -m riskgpu.modalgpu.launch report <name> [<name>]
```

- **`push`** starts each run it names on a GPU container of its own (`--gpu`: T4, L4, A10, A100-40GB, A100-80GB or H100; A10 by default), all in one app, and returns. Its trainer arguments are checked first by the trainers' own parsers, and the plateau stop is required as on Kaggle (`--stop-when` and `--stop-key`, or `--no-stop`). Each run's own arguments follow the shared ones (`--run-args <name>="<args>"`), so a seed pair, or the same recipe at several sizes of net, is one push. All of a push's runs share its `--hours`, so runs whose lengths differ by much go in separate pushes.
- **`--dry-run`** checks the arguments as a push would and prints each run's arguments, the inputs it would upload and its worst case in dollars, then stops without asking Modal anything: the way to see a sweep's exact cost before spending.
- **`status`, `stop`, `fetch` and `report`** take several names, one run after another, so a sweep is followed with one command.
- **Detached.** The push starts an ephemeral app in detached mode (the Python form of `modal run --detach`) and spawns the runs in it, so nothing of the laptop's is needed once the command returns: the app lives while its runs do and stops by itself when the last ends. One app per push, rather than a deployed app the pushes share, keeps each push's code in its own image and leaves nothing to tidy up.
- **The code** is this checkout's GPU package at HEAD (its code and committed data), put in the image as it stands there; the push refuses a GPU package with changes not committed, and the run records the commit it trained on. Nothing has to reach GitHub first, unlike a Kaggle session. `--uncommitted` ships the working tree instead, for testing the launcher itself, and the run records its commit as uncommitted.
- **Two Volumes.** A run's folder lives on the `risk-runs` Volume at its local path (`runs/selfplay/<name>` or `runs/imitate/<name>`), where the trainer writes its checkpoints as it always does. The push replaces that folder with the local one, which stays the run's source of truth, so a run resumes on Modal from wherever it was trained last; the one exception is a resume push (below), which keeps the Volume's folder because it is ahead.
- **Every checkpoint is committed.** Modal commits a Volume in the background every few seconds and once more when a container shuts down, but a container the workspace's spend cap stops, or one killed outright, may not shut down cleanly, and a PPO run that runs into the cap has to resume from its last checkpoint. So the container commits the run's folder itself whenever the trainer saves `latest.pt`: the trainer prints a line after every iteration, after that iteration's save, and the session, which already reads those lines to keep the run's output, commits on the line of each checkpoint's iteration, and once more when the trainer exits after its last save. The commit follows the trainer's own event, never a clock. Everything else the run reads that git doesn't carry (the blitz tables, every checkpoint its arguments name, the panel's anchors, an imitation's data) goes to the `risk-data` Volume, which keeps a manifest of each file's hash: a push uploads only what is missing there or changed, so an imitation's gigabytes of data go up once.
- **`status`** asks Modal for the run's container: running, finished, or failed with the error it raised, and the last line of the run's log (`log.jsonl`, which reaches the Volume as the run goes), with the last line of its output and the end of its errors when it failed, read from the Volume.
- **`stop`** kills the run's container. Its folder keeps what it saved, and `fetch` brings it back.
- **`fetch`** copies the run's folder from the Volume over its local folder once the container has ended, with Kaggle's guard: it refuses if the run's `latest.pt` (an imitation's `best.pt`) changed here since the push, since it would overwrite that work. It then prints the report.
- **A resume push.** Pushing a PPO run again while its last push is still unfetched (stopped, cut by the cap, out of hours, or failed) continues it on the Volume: the push leaves the run's folder there as it is and starts a container on it, and the trainer resumes from its `latest.pt` with its optimizer, its league and its iteration count. The recipe is the run's own: the trainer refuses a changed `--bootstrap` on resume, and the launcher refuses it first where the local `latest.pt` says what it was. The push refuses while the last container is still running (two containers never train one folder), if `latest.pt` changed here since the last push (the two folders have forked: fetch, or start a new run), and if the run stopped on its plateau, which is a diagnosis, not a cue for more hours. An imitation's unfetched push is fetched first, since an imitation can't resume. A fetch afterwards brings back the whole run, every container's work in one folder.
- **`report`** is Kaggle's: a PPO run's panel readings with their verdicts and its sharp readings, or an imitation's last log line and its two readings.

## After training, the readings

The container reads its run once it stops, as a Kaggle session does (`kaggle.md`), with the session's own code: a PPO run's sharp readings (its checkpoints at its last three headline readings, newest first, on the panel at `--sharp-games` a check, 4,096 by default), an imitation's held-out agreement and its panel. One GPU does both, in turn.

## A reading of existing checkpoints

Some questions need a GPU but no training: a reading of checkpoints already trained, by one of the diagnostic tools (`selfplay/search.py`, a rollout search against the raw net; `selfplay/calibrate.py`, the value head against real outcomes; `selfplay/panel.py`, the stage-0 panel on any checkpoint). A push of readings runs those on Modal instead of the eGPU.

```bash
python -m riskgpu.modalgpu.launch push --read <name>="<tool> <its arguments>" [--read ...] [--gpu A10] [--hours 2] [--dry-run]
```

- **Each `--read` is one reading on a container of its own**, named, its tool one of `search`, `calibrate` and `panel` (any other module is refused), and its arguments the tool's own, passed through verbatim. A push is either runs or readings, never both, and a push of readings takes none of the training options.
- **Its arguments are checked by the tool's own parser** before Modal is asked anything or anything is uploaded, so an argument the tool would refuse costs no container. The launcher also refuses what would waste one: a `--device` other than the GPU, bf16 on a T4 (each tool's default is bf16 on CUDA, so a T4 reading names `--no-bf16`), and an `--out`, since the output is the launcher's. On every other GPU the reading's precision is its own: it is a measurement, and precision may be what it compares.
- **Its inputs are the checkpoints its arguments name**, given as paths under `runs/` relative to the GPU folder, with the blitz tables and, for the panel, its anchors. Each must be in this checkout; they go to the data Volume where missing or changed, as a run's inputs do. A checkpoint of a run still on Modal is read once it has been fetched.
- **It runs in `runs/readings/<name>/`** on the runs Volume: the tool's output as `<tool>.json`, its captured output as `out.txt` and `err.txt`, and the container's record of its starts. A name whose local folder already holds anything is refused: a reading is never redone in place, a new one gets a new name.
- **The container runs the session with that reading alone in its queue**: no training, no league, no sharp readings after it. The reading is stopped five minutes before `--hours`, as a run's readings are, leaving the last write to the Volume; the tools write their output only at the end, so a reading stopped there has no output, and its hours are sized from the tool's measured cost with room to spare. A restarted container reads again from the start, inside its first start's deadline.
- **The same commands follow it.** `status` shows the container and the last line of the reading's output; `stop` kills it; `fetch` brings its folder into `runs/readings/<name>/` here once it has ended, refusing if that folder has gained anything since the push, and prints the report; `report` prints the reading in its tool's own table (the search's sides and overrules, calibration's tables, the panel's readings). The budget, the dry run, the CUDA check at start and the refusal of uncommitted code are the training push's, unchanged; a reading holds four cores and 16 GiB.

## An imitation

`push --imitate` runs `imitate.py train` with its arguments after `--`, each run in `runs/imitate/<name>/`, as Kaggle's imitation sessions do: a fresh run every time (a name whose folder already holds a trained net is refused), its data on the data Volume, its training capped by the container's hours. Its network's size is the trainer's own `--width`, `--layers` and `--heads`; a width the heads don't divide and a `--device` other than the GPU are refused before anything is uploaded, since either would fail or idle a container that is already paid for.

- **A comparison of sizes reads the fit.** Beside the held-out read that keeps `best.pt`, the trainer reads a fixed sample of the run's own training decisions at every checkpoint, the same decisions for any size of net at the same `--fraction`, and logs its agreement (`fit_main`, `fit_move`). That is the capacity reading: a net that can't fit what it trains on is short of size or of steps. `train_agree` is kept, the mean over the minibatches since the last read while the weights moved, which is what runs from before the fixed read have. `report` and `fetch` print the net's size, its epochs, the fit and `train_agree` after Kaggle's report.
- **`--no-panel`** reads a trained imitation on its held-out agreement alone. The panel's games cost GPU time that a comparison of fits doesn't need, and the panel can be read later, on the laptop or in another push, from the fetched `best.pt`.
- **The readings' hours are the push's `--read-hours`**: the agreement read alone is one pass over the held-out decisions without training, so a push without the panel needs far less than the default two.

## What a run costs and when it stops

- **`--hours` bounds the container and so the money.** It is the container's Modal timeout. The training is given the hours less `--read-hours` and the last five minutes, and saves `latest.pt` there; no reading starts after the hours, and one still going is stopped, leaving the five minutes for the last write to the Volume. A container is at most 24 hours, Modal's longest.
- **The money can't overrun; the rule is about not wasting it.** The workspace's spend cap is $30, the month's credit, set on Modal's dashboard, so no push can spend past it. When the cap is reached Modal stops the workspace's work; its docs don't say how gently, so the launcher assumes a container can be stopped at any moment without its last commit.
- **The push shows its worst case.** The worst case is each run's hours at its GPU's rate and the rates of the cores and memory it holds (four cores; 16 GiB for PPO, 32 for an imitation, which holds its data in memory), all at Modal's published rates. Beside it the push shows the month's spend (`modal billing summary`) and, for every pushed container Modal says is still running, the hours it may still hold.
- **A run that can resume may run into the cap.** A PPO run is pushed whatever its worst case, unless the month's credit is already spent: it trains until it ends or the cap stops it, keeping its last checkpoint, and is pushed again next month to resume. The push says when it may meet the cap.
- **A push that can't resume must fit.** An imitation starts afresh and a reading writes its output only at its end, so either one cut off by the cap has spent its money for nothing. It is refused when the month's spend, the worst case of every container still running and its own worst case would pass $30.
- **A resumable run in flight can crowd one out.** A PPO run in flight is allowed to run to the cap, so its worst case is real: it may take every dollar left, and an imitation or a reading started beside it could be cut off. While its worst case leaves no room, a push that can't resume is refused, naming the run; stopping it costs nothing but the training since its last checkpoint, and a resume push carries it on once the other has run. A warning alone would let a whole imitation's spend be lost.
- **So a month runs its short work first and its training last.** Readings and imitations fit inside the credit at their worst case; training takes what is left.
- **A dry run** checks the rule as far as it can without asking Modal: a push that can't resume and whose worst case alone passes $30 is refused, and a PPO push past it says it may meet the cap.
- **A run fails once, loudly.** Modal retries nothing (`retries=0`) and the launcher has no restart loop: a run that fails stays failed, `status` says why, and the next push resumes it. Modal may still restart a preempted container. A restarted container keeps its first start's deadline, so a restart never buys hours the push didn't pay for: a PPO run resumes from its last checkpoint, and an imitation, which can't resume, fails instead.
- **Precision is bf16 on every GPU but the T4**, which has none and trains with `--no-bf16`. The launcher refuses `--no-bf16` on any other GPU: bf16 is this host's recipe, so a Modal run is comparable with the eGPU's runs, not with Kaggle's full-precision ones.
- **A run stops on a plateau**, as on Kaggle: the trainer reads its `--stop-key` at every evaluation and stops on the verdict `--stop-when` names. A stop is the start of a diagnosis (the skill's `references/diagnosis.md`), never a cue to push the same recipe for more hours.
